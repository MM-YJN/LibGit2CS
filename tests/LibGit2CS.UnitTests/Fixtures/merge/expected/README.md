# Merge golden fixtures

These files are the byte-exact golden output for the merge golden tests,
generated by `generate-goldens.sh` (merge section).

## Golden types

| File pattern | Git command | C# API | Comparison |
|---|---|---|---|
| `merge_tree_<case>.txt` | `git merge-tree --write-tree --name-only --merge-base=<base> <ours> <theirs>` | `repo.MergeTreesAsync(base, ours, theirs)` | Tree OID (clean) or tree OID + conflict messages (conflict) |
| `merge_tree_stages_<case>.txt` | `git read-tree -m <base> <ours> <theirs>` + `git ls-files -s` | `repo.MergeTreesAsync(...)` + `IndexGoldenFormatter.FormatLsFiles` | Full index entries including conflict stages (0/1/2/3) |
| `merge_base_<case>.txt` | `git merge-base <a> <b>` | `repo.MergeBaseFindAsync(a, b)` | Single merge-base OID |
| `merge_commit_<case>.txt` | `git merge --no-ff --no-commit <theirs>` (pinned dates) + `git ls-files -s` | `repo.MergeCommitsAsync(our, their)` + `IndexGoldenFormatter.FormatLsFiles` | Full index entries (recursive merge, may differ from tree-level for criss-cross) |

## Tree-level vs commit-level

`MergeTreesAsync` performs a three-way merge with a single explicit base (from
`MergeBaseFindAsync`). The tree-level goldens use `--merge-base=<base>` to pin
the same single base, making the comparison fair.

`MergeCommitsAsync` performs a recursive merge (computes a virtual base
for criss-cross histories). The commit-level goldens use `git merge` which
also does recursive merge.

For criss-cross histories (branchB, branchC, etc. — all branches in the
merge-recursive fixture have 2+ merge bases), the tree-level merge with a
single base may conflict while the recursive commit-level merge is clean.
Both are correct — they answer different questions.

## Determinism (commit-level only)

Commit-level goldens (`merge_commit_*.txt`) require pinned environment
variables for reproducible results:

```
GIT_AUTHOR_DATE=2000-01-01T00:00:00
GIT_COMMITTER_DATE=2000-01-01T00:00:00
GIT_AUTHOR_NAME=Test Author
GIT_AUTHOR_EMAIL=test@example.com
GIT_COMMITTER_NAME=Test Author
GIT_COMMITTER_EMAIL=test@example.com
```

These are set in `generate-goldens.sh` and do not affect tree-level or
merge-base goldens (which are date-independent).

## Regeneration

```sh
./tests/LibGit2CS.UnitTests/generate-goldens.sh [path-to-libgit2]
```

The script extracts `Fixtures/merge/merge-recursive.zip` to a temp dir,
runs the git commands, and writes the expected files here. Idempotent
(overwrites in place).

## Fixture

The merge goldens use `Fixtures/merge/merge-recursive.zip` (packaged by
the apply section of `generate-goldens.sh` from
`~/repo/libgit2/tests/resources/merge-recursive/`). The fixture contains
23 branches (branchA-1 through branchK-2) with criss-cross histories,
content conflicts, and recursive merge scenarios.
